## Kotlin 위임 프로퍼티 (Delegated Property)

- **위임 프로퍼티** : 프로퍼티의 getter/setter 로직을 다른 객체(**delegate**)에 맡기는 기능. `by` 키워드로 프로퍼티와 delegate를 연결
- 작동 방식 : delegate가 값을 실제로 관리하고, 접근·수정 시점마다 커스텀 로직(지연 초기화, 검증, 로깅 등)을 끼워 넣을 수 있음

---

- **지연 초기화 (`lazy`)** : 프로퍼티에 처음 접근하는 시점에만 초기화 람다가 실행되고, 이후엔 캐시된 값을 반환

```kotlin
val lazyValue: String by lazy {
    println("Computed!")
    "Hello, Kotlin!"
}
// lazyValue에 처음 접근할 때만 "Computed!"가 출력됨
```

- **관찰 가능한 프로퍼티 (`Delegates.observable`)** : 값이 바뀔 때마다 콜백이 호출됨

```kotlin
var observableValue: String by Delegates.observable("Initial value") { _, old, new ->
    println("Value changed from $old to $new")
}
observableValue = "New value"   // Value changed from Initial value to New value
```

- **거부 가능한 프로퍼티 (`Delegates.vetoable`)** : observable과 비슷하지만, 조건에 따라 변경 자체를 거부할 수 있음

```kotlin
var vetoableValue: Int by Delegates.vetoable(0) { _, old, new -> new > old }
vetoableValue = 5   // 허용됨 (5 > 0)
vetoableValue = 2   // 거부됨 (2 > 5 가 false라 값이 바뀌지 않음)
```

- **Map 위임** : 프로퍼티 값을 map에서 읽어오는 동적 프로퍼티 (JSON 파싱 등에 유용)

```kotlin
class User(val map: Map<String, Any?>) {
    val name: String by map
    val age: Int by map
}

val user = User(mapOf("name" to "John Doe", "age" to 30))
println(user.name)   // John Doe
println(user.age)    // 30
```

---

- **로컬 위임 프로퍼티** : 함수나 블록 내부의 지역 변수에도 `by`로 delegate를 적용할 수 있음

```kotlin
class Delegate {
    operator fun getValue(t: Any?, p: KProperty<*>): Int = 1
}

fun box(): String {
    val prop: Int by Delegate()   // 지역 변수도 위임 가능
    return if (prop == 1) "OK" else "fail"
}
```

- **Pro Tip: `lazy`의 내부 메커니즘**
  - 핵심은 `Lazy<T>` 인터페이스 : `value`(최초 접근 시 계산, 이후 캐시 반환), `isInitialized()`(초기화 여부 확인)
  - 내부적으로 `UNINITIALIZED_VALUE`라는 마커 객체로 "아직 초기화 안 됨"을 추적하고, 초기화가 끝나면 람다 참조를 `null`로 비워 메모리 누수를 방지
  - `lazy()`는 스레드 안전성 모드에 따라 서로 다른 구현을 반환

  | 모드 | 구현체 | 메커니즘 | 특징 |
  |---|---|---|---|
  | `NONE` | `UnsafeLazyImpl` | 동기화 없이 단순 검사 | 가장 빠르지만 스레드 안전성 없음 (단일 스레드 전용) |
  | `SYNCHRONIZED` (기본값) | `SynchronizedLazyImpl` | 이중 검사 잠금(double-checked locking) | 멀티스레드에서 안전, 초기화는 정확히 한 번만 |
  | `PUBLICATION` | `SafePublicationLazyImpl` | CAS(compare-and-set), lock-free | 여러 스레드가 동시에 계산할 수 있지만, 값은 하나만 채택됨 (중복 계산 가능) |

---

- **Pro Tip: `by lazy { }`가 바이트코드로 컴파일되는 방법**
  - 컴파일러는 프로퍼티 값을 직접 담는 필드 대신, `Lazy` 타입의 `xxx$delegate` 필드를 생성
  - 리플렉션 지원을 위한 `$$delegatedProperties` 메타데이터 배열(프로퍼티 이름, getter 시그니처 등)도 함께 생성
  - public getter는 `delegate.getValue(this, property)`를 호출하도록 변환됨 → 실제 "지연" 동작은 `Lazy.getValue()` 내부에서 일어남

```kotlin
class UserSession {
    val heavyUserData: String by lazy {
        println("Computing heavy user data...")
        "User Profile Data"
    }
}
// 컴파일 결과(개념적으로):
// private final Lazy heavyUserData$delegate = LazyKt.lazy(...)
// public String getHeavyUserData() { return heavyUserData$delegate.getValue(...) }
```

## 🔑 정리: 특징 · 장단점 · 예시

### 특징
- `by` 키워드로 getter/setter 로직을 프로퍼티 밖의 재사용 가능한 컴포넌트(delegate)로 분리
- 표준 라이브러리에 `lazy`, `Delegates.observable`, `Delegates.vetoable` 등 바로 쓸 수 있는 delegate가 이미 제공됨

### 장점
- 지연 초기화·변경 감지·유효성 검증 같은 반복 패턴을 보일러플레이트 없이 구현 가능
- 같은 delegate를 여러 프로퍼티·클래스에서 재사용할 수 있어 로직 중복이 줄어듦
- 프로퍼티 관리 로직과 비즈니스 로직이 분리되어 클래스 본문이 더 깔끔해짐

### 단점
- 내부적으로 `getValue`/`setValue` 함수 호출을 거치기 때문에, 단순 필드 접근보다 약간의 오버헤드가 있음
- 기본 `lazy`는 `SYNCHRONIZED` 모드라 동기화 비용이 있음 — 단일 스레드에서만 쓰인다면 `LazyThreadSafetyMode.NONE`이 더 빠름
- `by`가 내부적으로 무엇을 하는지 모르면, "왜 커스텀 getter처럼 동작하지?"처럼 동작 원리를 파악하기 어려워 처음엔 진입 장벽이 있음

### 예시
```kotlin
// 커스텀 delegate: 항상 0 이상만 허용하는 프로퍼티
class NonNegative(private var value: Int) {
    operator fun getValue(thisRef: Any?, property: KProperty<*>): Int = value
    operator fun setValue(thisRef: Any?, property: KProperty<*>, newValue: Int) {
        value = if (newValue >= 0) newValue else 0
    }
}

class Account {
    var balance: Int by NonNegative(0)
}

val account = Account()
account.balance = -100   // 내부적으로 0으로 보정됨
println(account.balance) // 0
```
