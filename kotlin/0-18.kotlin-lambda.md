## 0-18. Kotlin 람다 표현식

- **람다 표현식** : 값으로 취급할 수 있는 익명 함수. 인수로 전달하거나, 반환하거나, 변수에 저장 가능. `{ 매개변수 -> 본문 }` 형태로 작성

```kotlin
val greet = { name: String -> "Hello, $name" }
println(greet("skydoves"))   // Hello, skydoves
```

- **축약 문법** : 매개변수가 하나뿐이면, 암시적 `it`으로 생략 가능

```kotlin
val square = { it: Int -> it * it }
println(square(4))   // 16
```

---

- **고차 함수와의 사용** : `map`, `filter`, `forEach` 같은 컬렉션 함수에서 람다가 자주 쓰임

```kotlin
val numbers = listOf(1, 2, 3, 4, 5)
println(numbers.map { it * 2 })   // [2, 4, 6, 8, 10]
```

- **스코프의 변수 캡처** : 람다는 자신을 둘러싼 스코프의 변수를 캡처해서 직접 읽고 수정할 수 있음

```kotlin
var counter = 0
val increment = { counter++ }
increment()
increment()
println(counter)   // 2
```

## 🔑 정리: 특징 · 장단점 · 예시

### 특징
- 람다는 "이름 없는 함수"이자 "값"이라서, 변수에 담거나 다른 함수에 넘기는 식으로 자유롭게 다룰 수 있음
- 둘러싸는 스코프의 변수를 캡처(클로저)할 수 있어, 그 변수의 최신 상태를 계속 참조/수정 가능

### 장점
- `map`/`filter` 등과 결합하면 루프를 직접 작성하지 않고도 의도를 선언적으로 표현할 수 있음
- 콜백·이벤트 핸들러를 익명 클래스 없이 한 줄로 표현 가능
- 변수 캡처 덕분에 간단한 상태를 가진 함수(카운터, 누적기 등)를 쉽게 만들 수 있음

### 단점
- 변수를 캡처하는 람다를 오래 들고 있으면(리스너 등), 캡처된 객체가 예상보다 오래 메모리에 남아 누수로 이어질 수 있음
- 람다 체인이 길어지면 디버깅 시 스택 트레이스가 복잡해져서 일반 함수보다 추적이 어려울 수 있음
- 매개변수가 여러 개인데 전부 `it`처럼 암묵적으로 처리하려고 하면 오히려 가독성이 떨어짐 (이때는 이름을 명시하는 게 낫음)

### 예시
```kotlin
// 캡처한 변수로 호출 횟수를 추적하는 간단한 람다
var callCount = 0
val logged: (String) -> Unit = { message ->
    callCount++
    println("[$callCount] $message")
}

logged("start")   // [1] start
logged("done")    // [2] done
```
