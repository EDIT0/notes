## 0-20. Kotlin 확장(Extension)

- **확장(Extension)** : 기존 클래스의 소스 코드를 수정하지 않고 새 함수/프로퍼티를 추가하는 기능. 소스에 접근할 수 없는 표준 라이브러리나 서드파티 클래스를 보강할 때 특히 유용

```kotlin
fun Int.isEven(): Boolean = this % 2 == 0
println(4.isEven())   // true — Int 클래스를 직접 수정하지 않았는데도 사용 가능
```

- **확장 프로퍼티** : 비슷한 방식으로 프로퍼티도 추가할 수 있지만, **상태를 저장할 수 없고** getter에 대한 문법적 편의일 뿐

```kotlin
val String.firstChar: Char
    get() = this[0]

println("Hello".firstChar)   // H
```

- companion object에도 확장을 추가할 수 있음

```kotlin
val String.Companion.Empty: String
    get() = ""

val fakeUser = User.createUser(name = String.Empty)   // User.createUser(name = "") 대신
```

---

- **장점** : 가독성 향상(의도를 표현력 있게 드러냄) / 모듈성(원본 클래스를 안 건드려도 기능 추가) / 재사용성(여러 곳에서 재사용, 보일러플레이트 감소)

- **단점**
  - 혼란 유발 : 멤버 함수와 이름이 같으면 **멤버 함수가 항상 우선**되어 직관과 다르게 동작할 수 있음
  - 과도한 사용은 코드 구성을 해침 : 여러 파일/모듈에 흩어진 확장이 많아지면 API가 비대해지고 응집력이 떨어짐
  - 출처 추적이 어려움 : 대규모 코드베이스에서는 확장이 어디 정의돼 있는지 찾기 힘들어 디버깅이 어려워짐
  - 라이브러리/SDK를 설계할 때는 내부용 확장을 `internal`이나 `private`으로 제한해, 공개 API가 불필요하게 비대해지지 않도록 해야 함

---

- **Pro Tip: 확장 함수가 바이트코드로 컴파일되는 방법**
  - 확장 함수는 JVM에 개념 자체가 없기 때문에, 컴파일되면 **정적(static) 메서드**가 되고 수신자 객체는 그 메서드의 **첫 번째 매개변수**로 전달됨

```kotlin
fun String.addExclamation(): String = this + "!"
"skydoves".addExclamation()
// 개념적으로:
// public static String addExclamation(String receiver) { return receiver + "!"; }
```

  - 장점 : Java 쪽에서도 생성된 유틸리티 클래스를 통해 호출 가능(JVM 호환성) / 일반 정적 메서드 호출과 동일해서 추가 런타임 오버헤드 없음 / 원본 클래스를 전혀 건드리지 않음
  - 한계 : 진짜 멤버가 아니라서 **수신자 클래스의 private 멤버에 접근 불가** / 리플렉션으로 "그 클래스의 멤버"처럼 식별되지 않음

---

- **Pro Tip: `@JvmSynthetic`으로 Java에서 숨기기**
  - 확장 함수는 기본적으로 `public static` 메서드로 컴파일되어 **Java에서도 그대로 호출 가능**함 — 그런데 Kotlin 내부 DSL처럼 Java에 노출하고 싶지 않은 경우도 있음
  - `@JvmSynthetic`을 붙이면 생성된 메서드에 `ACC_SYNTHETIC` 플래그가 붙어, **Java 컴파일러가 직접 호출을 막고 IDE 자동완성에도 뜨지 않게** 됨 (리플렉션으로는 여전히 접근 가능하지만 권장되지 않음)

```kotlin
@JvmSynthetic
fun String.hiddenExclamation(): String = this + "!!!"
// Java에서: StringExtensionsKt.hiddenExclamation("x") 호출 시 컴파일 에러
```

  - `internal` 확장 함수도 바이트코드에서는 결국 `public` + 이름 맹글링으로 컴파일되는데, 여기에 `@JvmSynthetic`을 더하면 **모듈 내부(Kotlin)에서는 쓸 수 있지만 Java에서는 완전히 숨겨지는** 메서드를 만들 수 있음

## 🔑 정리: 특징 · 장단점 · 예시

### 특징
- "클래스를 수정하는 것"이 아니라 "클래스를 다루는 정적 유틸리티 함수를 멤버처럼 보이게 포장하는 것"이 확장의 본질 (바이트코드 수준에서 보면 명확해짐)
- 상속 없이도 기존 타입에 기능을 덧붙일 수 있어, 표준 라이브러리나 서드파티 타입도 자유롭게 확장 가능

### 장점
- `isEven()`, `firstChar` 처럼 도메인 언어에 맞는 표현을 만들어 코드 가독성을 크게 높임
- 원본 클래스/라이브러리를 건드리지 않고 기능을 추가하므로 안전하고 모듈적임
- `@JvmSynthetic`, `internal` 등과 결합하면 라이브러리 내부 전용 확장을 깔끔하게 숨길 수 있음

### 단점
- 멤버 함수와 이름이 겹치면 항상 멤버가 우선이라, 어떤 확장이 실제로 호출됐는지 헷갈릴 수 있음
- private 멤버에는 접근할 수 없어서, 캡슐화된 내부 상태를 다뤄야 하는 로직에는 적합하지 않음
- 여기저기 분산해서 선언하면 "이 타입에 어떤 기능이 있는지"를 한눈에 파악하기 어려워짐 (IDE의 자동완성에만 의존하게 됨)

### 예시
```kotlin
// 표준 라이브러리 타입에 도메인 특화 기능을 추가
fun List<Int>.average2(): Double = if (isEmpty()) 0.0 else sum().toDouble() / size

fun String.isValidEmail(): Boolean = contains("@") && contains(".")

println(listOf(1, 2, 3).average2())      // 2.0
println("user@example.com".isValidEmail()) // true
```
