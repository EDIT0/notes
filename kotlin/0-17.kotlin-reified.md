## 0-17. Kotlin reified

- **`reified`** : `inline` 함수에서만 쓸 수 있는 키워드로, JVM의 타입 소거를 우회해 **런타임에 제네릭 타입 `T`에 접근**할 수 있게 함
- 일반 제네릭 함수에서는 `value is T`, `T::class` 같은 연산이 컴파일 에러지만, `inline` + `reified`에서는 가능해짐

```kotlin
inline fun <reified T> isType(value: Any): Boolean = value is T

inline fun <reified T> printClassName() = println(T::class.java.name)
printClassName<String>()   // java.lang.String — Class 객체를 직접 넘길 필요가 없음
```

---

- **장점**
  - 타입 안전성 : 검사되지 않은 캐스트(`@Suppress("UNCHECKED_CAST")`)를 줄일 수 있음
  - 더 깔끔한 문법 : `Class<T>`를 매개변수로 직접 넘기지 않아도 됨
  - 런타임 리플렉션이 쉬워짐 : 타입 검사·클래스 메타데이터 접근을 함수 호출 하나로 처리

- **한계**
  - `inline` 함수에서만 사용 가능 (범용 제네릭 함수/클래스에는 적용 불가)
  - 과도하게 사용하면 `inline`의 단점(코드 비대화)을 그대로 물려받음

```kotlin
inline fun <reified T> List<Any>.filterByType(): List<T> = this.filterIsInstance<T>()

val mixedList = listOf(1, "Kotlin", 2.5, "Programming")
println(mixedList.filterByType<String>())   // [Kotlin, Programming]
```

---

- **Pro Tip: `inline` + `reified`가 바이트코드로 컴파일되는 방법**
  - **inline 메커니즘(코드 복사)** : 함수 호출 자체가 사라지고, 함수 본문이 호출 지점에 그대로 복사됨
  - **reified 메커니즘(타입 대체)** : 복사되는 과정에서 `T`가 **호출 시점에 실제로 쓰인 타입**으로 치환됨 → 바이트코드에는 이미 구체적인 타입만 남음

```kotlin
inline fun <reified T> isInstanceOf(value: Any): Boolean = value is T

isInstanceOf<String>(myString)   // 컴파일 후 개념적으로: myString instanceof String
isInstanceOf<Int>(myString)      // 컴파일 후 개념적으로: myString instanceof Integer
```

  - 이게 가능한 이유 : 함수가 인라인되지 않았다면 어디서든 호출 가능한 **단일 범용 바이트코드**가 되어야 하고, 그 경우 `T`는 결국 소거되어 알 수 없음. `inline`이 "호출 지점마다 다시 생성"을 가능케 해서, 그때그때 실제 타입을 박아 넣을 수 있는 것

---

## 🔑 정리: 특징 · 장단점 · 예시

### 특징
- `reified`는 `inline`이 만들어주는 "호출 지점마다 코드가 다시 생성된다"는 성질에 기대어, 타입 소거라는 JVM의 근본 제약을 컴파일 타임에 우회하는 기법
- `T::class`, `is T`처럼 평범한 제네릭에서는 막혀 있는 연산을 함수 안에서 자연스럽게 쓸 수 있게 해줌

### 장점
- `Class<T>` 매개변수를 따로 받지 않아도 되어, API 호출부가 `fetch<User>()`처럼 간결해짐
- 타입 캐스팅/검사를 라이브러리 내부로 숨길 수 있어, 사용하는 쪽 코드는 캐스팅 없이 타입 안전하게 작성됨

### 단점
- `inline` 함수여야만 하므로, 그 함수가 커지면 호출 지점마다 코드가 복사되어 바이너리가 커짐
- 인터페이스나 추상 메서드로는 `reified`를 선언할 수 없어 (구현체가 각각 달라 인라인할 수 없음), 다형적 설계와는 함께 쓰기 어려움
- 남용하면 "타입 매개변수가 왜 특별하게 동작하는지" 모르는 사람에게는 코드가 다소 마법처럼 보일 수 있음

### 예시
```kotlin
// Android에서 흔한 패턴: 타입으로 Fragment를 찾는 유틸리티
inline fun <reified T : Fragment> FragmentManager.findFragment(): T? =
    fragments.filterIsInstance<T>().firstOrNull()

val fragment = fragmentManager.findFragment<MyFragment>()   // Class 객체 없이 타입만으로 조회
```
