## 0-14. Kotlin init 블록

- **호출 시점** : 새 인스턴스가 생성될 때, **주 생성자 매개변수가 전달된 후 ~ 클래스 본문이 실행되기 전** 사이에 실행됨
- 주요 특징
  - 모든 보조 생성자보다 먼저, **클래스에 나타나는 순서대로** 실행됨
  - 주 생성자 매개변수에 직접 접근 가능 → 매개변수에 의존하는 초기화 로직 작성 가능
  - 한 클래스에 **여러 개**의 `init` 블록을 둘 수 있고, 정의된 순서대로 실행됨

```kotlin
class User(val name: String, val age: Int) {
    val isAdult: Boolean

    init {
        isAdult = age >= 18    // 생성자 매개변수(age) 기반으로 프로퍼티 계산
        println("User initialized: $name, age: $age, isAdult: $isAdult")
    }
}

val user = User("John Doe", 20)
// User initialized: John Doe, age: 20, isAdult: true
```

---

- **장점** : 생성자 매개변수에 의존하는 초기화 로직을 한곳에 모을 수 있음 / 여러 보조 생성자에 걸친 초기화 코드 중복을 방지 / 생성자 시그니처를 단순하게 유지하면서 설정 로직을 분리

- **중요 고려사항**
  - `init` 블록에서는 아직 초기화되지 않은 `lateinit` 프로퍼티에 접근할 수 없음
  - 여러 `init` 블록은 선언 순서대로 순차 실행
  - 어떤 생성자를 쓰든(주 생성자든 보조 생성자든) `init` 블록은 항상 실행되므로 초기화 일관성이 보장됨

---

- **Pro Tip: `init` 블록의 단점**
  1. **의도치 않은 사이드 이펙트** : 객체가 인스턴스화될 때마다 자동 실행되므로, 안에 네트워크 호출·로깅 같은 사이드 이펙트를 넣으면 예상 못한 시점에 실행될 수 있음
  2. **제한된 유연성** : 실행을 늦출 방법이 없어서, 아직 준비되지 않은 `lateinit` 프로퍼티 등에 접근하면 예외 발생
  3. **긴밀한 결합** : 복잡한 로직이 생성자 매개변수와 강하게 묶여, 테스트/유지보수가 어려워짐
  4. **성능 영향** : 무거운 연산(DB 쿼리, 파일 I/O 등)이 들어가면 객체 생성 자체가 느려짐
  5. **디버깅 어려움** : 생성 시점에 바로 예외가 터지기 때문에 원인 추적이 더 어려울 수 있음

  - **완화 방법** : `init`은 순수하고 단순하게 유지 / 복잡한 초기화는 팩토리 메서드·빌더로 분리 / 상황별 로직은 보조 생성자로 분산 / 무거운 연산은 지연 초기화(`lazy`)나 DI로 미루기

---

- **Pro Tip: `init` 블록이 바이트코드로 컴파일되는 방법**
  - `init` 블록은 별도의 메서드가 되는 게 아니라, **생성자(`<init>`) 안에 코드가 그대로 인라인**됨
  - 실행 순서 : 슈퍼클래스 생성자 호출 → 주 생성자 프로퍼티 초기화 → `init` 블록 코드(선언 순서대로)
  - 보조 생성자가 있는 경우, 보조 생성자는 `this(...)`로 주 생성자에 위임하므로 **`init` 블록은 보조 생성자 본문보다 먼저 실행**됨

```kotlin
class Message(val content: String) {
    init { println("Initializer block running.") }

    constructor() : this("Default Message") {
        println("Secondary constructor body running.")
    }
}

Message()
// 1) Initializer block running.           ← this(...)로 위임된 주 생성자 안에서 실행
// 2) Secondary constructor body running.  ← 보조 생성자 본문은 그 다음
```

## 🔑 정리: 특징 · 장단점 · 예시

### 특징
- `init` 블록은 "주 생성자 매개변수를 받은 직후 실행되는 설정 코드"라는 한 가지 역할에 집중된 구조
- 보조 생성자가 몇 개든, `init` 블록은 모든 생성 경로에서 공통으로 실행됨 (주 생성자에 위임하는 구조 덕분)

### 장점
- 생성자 자체를 복잡하게 만들지 않고도, 매개변수 기반 검증/계산 로직을 깔끔하게 추가할 수 있음
- 여러 보조 생성자가 있어도 초기화 로직을 중복 작성할 필요가 없음

### 단점
- 사이드 이펙트(네트워크 호출, 로깅 등)를 넣으면 객체가 생성될 때마다 의도치 않게 실행되어 추적하기 어려운 버그로 이어질 수 있음
- 무거운 연산을 넣으면 객체 생성 자체가 느려짐 — 생성과 "준비"를 분리하고 싶다면 팩토리 메서드나 지연 초기화가 더 적합
- 생성 시점에 예외가 발생하면 (0으로 나누기 등) 스택 트레이스만 보고 원인을 파악하기가 상대적으로 어려움

### 예시
```kotlin
class Order(val items: List<String>, val couponCode: String?) {
    val totalCount: Int
    val hasDiscount: Boolean

    init {
        require(items.isNotEmpty()) { "Order must contain at least one item." }  // 검증
        totalCount = items.size                                                   // 파생값 계산
        hasDiscount = couponCode != null
    }
}
```
