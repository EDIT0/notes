## 0-15. Kotlin 고차 함수

- **고차 함수** : 다른 함수를 **매개변수로 받거나**, **함수를 반환**하거나, 둘 다 하는 함수. 함수 타입은 `(InputType) -> ReturnType`으로 표기

```kotlin
fun higherOrderFunction(input: Int, operation: (Int) -> Int): Int {
    return operation(input)
}

fun double(x: Int) = x * 2
println(higherOrderFunction(5, ::double))   // 10 — 함수를 매개변수로 전달
```

- **함수를 반환하는 예**

```kotlin
fun operation(type: String): (Int, Int) -> Int = when (type) {
    "add" -> { a, b -> a + b }
    "multiply" -> { a, b -> a * b }
    else -> { _, _ -> 0 }
}

val addOperation = operation("add")
println(addOperation(3, 4))   // 7
```

---

- **실제 사용 사례**
  - 컬렉션 연산 : `map`, `filter`, `reduce` 등이 전부 고차 함수

```kotlin
val numbers = listOf(1, 2, 3, 4)
println(numbers.map { it * 2 })   // [2, 4, 6, 8]
```

  - 이벤트/콜백 처리

```kotlin
fun performAction(onComplete: () -> Unit) {
    println("Performing action...")
    onComplete()
}
performAction { println("Action completed!") }
```

---

- **장점**
  - 재사용성 : 핵심 로직과 구체적인 동작을 분리해 모듈성을 높임 (같은 구조에 다른 함수를 꽂아 다른 결과를 얻음)
  - 가독성 : `map`/`filter`/`reduce` 같은 표현으로 장황한 루프/조건문 없이 의도를 바로 드러냄
  - 유연성 : 함수를 일급 시민으로 다뤄, 런타임에 동작을 동적으로 구성/교체 가능 (콜백, UI 렌더링 로직 등)
  - 추상화 : 제어 구조/알고리즘을 일반화해서 다양한 타입·상황에서 재사용 가능한 유틸리티로 만들 수 있음

---

- **Pro Tip: 고차 함수가 바이트코드로 컴파일되는 방법**
  - 함수 타입은 Kotlin 표준 라이브러리의 **함수 인터페이스**(`Function0<R>`, `Function1<P, R>`, `Function2<P1, P2, R>` ...)로 변환됨

```kotlin
fun higherOrderExample(operation: (Int) -> Int): Int = operation(10)
// 개념적으로: int higherOrderExample(Function1<Integer, Integer> operation) { return operation.invoke(10); }
```

  - 전달된 람다는 해당 함수 인터페이스를 구현하는 **익명 클래스**(또는 `invokedynamic` 바이트코드 명령으로 런타임에 생성되는 클래스)로 컴파일됨
  - `invokedynamic`(Java 7+)을 쓰면 익명 클래스를 미리 만들어두지 않고 JVM이 런타임에 생성해, 오버헤드를 줄임

  - **`inline` 함수** : 람다 본문을 호출 지점에 **직접 삽입**해서, 함수 객체/익명 클래스 생성 자체를 없애버림

```kotlin
inline fun inlineHigherOrderExample(operation: (Int) -> Int): Int = operation(10)
val result = inlineHigherOrderExample { it * 2 }
// 컴파일 결과(개념적으로): val result = 10 * 2   ← 람다 호출이 아니라 코드 자체가 그대로 삽입됨
```

## 🔑 정리: 특징 · 장단점 · 예시

### 특징
- 함수를 값처럼 취급(매개변수로 전달/반환/변수에 저장)할 수 있게 해주는 기능 — Kotlin 함수형 프로그래밍의 기반
- 내부적으로는 `FunctionN` 인터페이스 + 익명 클래스(혹은 `invokedynamic`)로 컴파일됨

### 장점
- 알고리즘의 "뼈대"와 "구체적인 동작"을 분리해, 같은 뼈대를 여러 상황에 재사용 가능
- `map`/`filter` 등으로 반복되는 루프 코드를 줄이고 의도를 선언적으로 표현
- 콜백/리스너 같은 패턴을 익명 클래스 없이 람다 하나로 간결하게 표현

### 단점
- 람다가 익명 클래스로 컴파일되면, 호출마다 객체가 생성되어 (특히 반복문 안에서) 약간의 오버헤드와 GC 압박이 생길 수 있음 — 성능이 중요한 구간이면 `inline` 고려
- 람다 체인이 길어지면(`map` → `filter` → `map` ...) 디버깅 시 스택 트레이스를 추적하기가 일반 루프보다 어려울 수 있음
- 함수를 반환하는 고차 함수를 과하게 쓰면, 실제로 어떤 동작이 실행되는지 추적하려고 여러 단계를 거슬러 올라가야 해서 가독성이 떨어질 수 있음

### 예시
```kotlin
// 고차 함수로 "재시도 로직"이라는 뼈대를 재사용
fun retry(times: Int, action: () -> Boolean): Boolean {
    repeat(times) {
        if (action()) return true
    }
    return false
}

val success = retry(3) {
    println("Trying...")
    Math.random() > 0.7   // 서로 다른 조건을 자유롭게 끼워 넣을 수 있음
}
```
